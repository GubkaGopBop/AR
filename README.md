# Практическая работа 4 — WebXR AR hit-test

Приложение на Three.js 0.186.0 размещает одно офисное компьютерное кресло в натуральную величину на найденной плоскости. Высота модели около 1,28 м, ширина около 0,66 м. Кольцо показывает место размещения. После тапа матрица объекта сохраняется в координатах `local-floor`; камера не является родителем кресла.

Интерфейс содержит название и две кнопки: «Начать AR» и «Посмотреть кресло». В просмотре модели остаётся только кнопка выхода; вид поворачивается перетаскиванием.

## Запуск на компьютере

Откройте терминал в этой папке и выполните:

```powershell
python -m http.server 8000
```

Откройте http://localhost:8000. Двойной щелчок по HTML не подходит для загрузки модулей. Без WebXR доступен просмотр кресла с поворотом вида перетаскиванием. Он не использует камеру и не проверяет AR-трекинг.

## Запуск AR на телефоне

Разместите содержимое этой папки на HTTPS-хостинге (например, GitHub Pages). Папка `vendor` тоже обязательна. Откройте HTTPS-ссылку в браузере и на устройстве, поддерживающих `immersive-ar`, `hit-test` и `local-floor`. Наличие обычной камеры само по себе недостаточно.

1. Нажмите «Начать AR» и разрешите доступ.
2. Медленно двигайте телефон над освещённым полом с различимыми деталями.
3. Дождитесь зелёного кольца и направьте его в нужное место.
4. Коснитесь области камеры или нажмите «Поставить кресло».
5. Обойдите кресло: он должен сохранять своё место.
6. Для нового места нажмите «Разместить заново». Для завершения — «Выйти».

`dom-overlay` запрашивается как необязательная функция. Если браузер не выводит HTML в AR, используйте тап по области камеры и системную кнопку завершения XR; для повторного размещения завершите сеанс и запустите снова.

HTTP по сетевому IP компьютера не является защищённым контекстом на телефоне. `localhost` телефона относится к самому телефону. Для доступа к локальному серверу через USB можно настроить перенаправление порта в инструментах разработчика браузера; проще использовать HTTPS-хостинг.

## Как устроено размещение

- Сессия создаётся непосредственно из обработчика кнопки через `navigator.xr.requestSession('immersive-ar', ...)`.
- `hit-test` и `local-floor` входят в `requiredFeatures`.
- `renderer.xr.setReferenceSpaceType('local-floor')` задаёт систему координат сцены. Three.js запрашивает её при `setSession`.
- Источник `XRHitTestSource` получается из `session.requestHitTestSource` в пространстве `viewer`. Это луч по направлению взгляда. `entityTypes: ['plane']` ограничивает поиск плоскостями.
- В каждом XR-кадре используется `frame.getHitTestResults(hitTestSource)`. Поза результата получается через `hit.getPose(renderer.xr.getReferenceSpace())`.
- Матрица позы переносится в кольцо. В `placement.js` при тапе матрица копируется в кресло **один раз**. Кресло и кольцо — независимые дочерние объекты сцены; `matrixAutoUpdate = false`.
- Все детали кресла собраны в одну группу в `chair.js`. Колёса касаются локальной плоскости y=0; при размещении группа переносится целиком.
- Когда кресло установлено, новые результаты hit-test не меняют его положение. При потере позы камеры новые размещения блокируются. Библиотека не рисует XR-вид без валидной позы камеры.
- После завершения сеанса источник отменяется (`cancel`), маркер и кресло скрываются. Положение не сохраняется между сеансами.

World tracking зависит от устройства и обстановки. Копирование матрицы устраняет следование за камерой в логике приложения, но не гарантирует отсутствие физического дрейфа системы трекинга. XRAnchor не требуется заданием и не используется.

## Что проверено

10 октября 2026 года:

- синтаксис JavaScript;
- загрузка локальных модулей и настоящий WebGL в Chrome;
- интерфейс на экранах 1000 × 800 и 390 × 844, просмотр модели и выход;
- интеграционная имитация XR с реальной математикой Three.js: параметры сессии, пространства координат, маркер, отсутствие размещения без поверхности, тап и DOM-кнопка, неизменность матрицы кресла при новом hit-test и движении камеры, сброс, потеря трекинга, скрытие сессии, защита от двойного select, отмена источника, повторный старт, отказ в доступе.

Проверки находятся в `../Отчёты/qa_pr4/check.cjs`. Имитация использует подмену XR API и рендерера, а не WebXR Emulator Extension. **Реальное устройство и физическое удержание кресла ещё не проверены.**

## Проверка на устройстве перед сдачей

Проверьте появление кольца и размещение на полу, обход объекта и изменение расстояния до него, отсутствие повторного переноса от второго тапа, сброс, остановку и повторный старт. Временно направьте камеру на однотонную поверхность и верните её к исходному месту. При отказе в разрешении должна появиться понятная ошибка. Запишите модель устройства, браузер и фактический результат; не выдавайте просмотр без камеры за AR-тест.

## Коротко для защиты

`app.js` запускает AR и в каждом кадре узнаёт, где луч камеры пересекает реальную плоскость. Зелёное кольцо показывает найденную точку. `placement.js` копирует положение и ориентацию кольца в кресло при тапе. Кольцо может двигаться, камера может двигаться, но матрица установленного кресла не обновляется. Все позы переведены в одну систему `local-floor`, поэтому они согласованы со сценой.
